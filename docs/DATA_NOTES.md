# Аудит DEV — контрольная точка раздела 1

## Настоящая модель: измерения, 2026-11-07

Выполнены настоящие запросы к OpenAI: запрошенная модель `gpt-4.1-mini`, возвращённая версия `gpt-4.1-mini-2025-04-14`, `is_demo=false`. Пробные запуски выявили ошибки структуры ответа, поэтому промпт и внутренняя схема последовательно обновлены до `cqa-v5`. Схема требует согласованную пару `checked_range` / `expected_action`, а ответ `answered` без диапазона — хотя бы один ID доказательства. Правила доменной проверки не ослаблялись. Версия промпта входит в ключ кеша.

Полный DEV на v5 и контрольная репетиция завершены: в каждом запуске оценены 65/65 разговоров. В полном DEV все ответы приняты с первой попытки; в репетиции две дополнительные попытки потребовались после отклонения ответов проверкой. HTTP 429 не зафиксирован. `C` — заданный `LLM_MAX_CONCURRENCY`; время — фактическое ожидание CLI/опроса API, а не сумма длительностей отдельных запросов. В пробе с одним разговором настройка C=4 не означает четыре одновременных запроса.

«Ошибки ответов» учитывают все HTTP 200 попытки, не приведшие к принятой оценке, включая повторы в успешно завершившихся разговорах; это не ошибки HTTP. Во всех семи экспериментах 219 попыток вернули HTTP 200, HTTP 429 не обнаружен. Итого, включая неуспешные попытки: 1 423 949 входных, 212 443 выходных, 612 608 кешированных входных токенов; расчётная стоимость — **$0.7257060**. Из 219 ответов 16 отклонены проверкой; три разговора в ранних экспериментах остались без принятой оценки. Финальные DEV и репетиция завершились без неуспешных разговоров. Разговоры в разных экспериментах повторяются, поэтому их суммы не являются числом уникальных разговоров.

Стоимость рассчитана по стандартному тарифу GPT-4.1 mini: вход $0.40, кешированный вход $0.10, выход $1.60 за миллион токенов; тариф проверен 2026-11-07 по [официальной странице модели](https://developers.openai.com/api/docs/models/gpt-4.1-mini). Кешированные токены уже входят во входные: формула `((input - cached) × 0.40 + cached × 0.10 + output × 1.60) / 1 000 000`. Это обычные запросы Responses API с локальной очередью, а не OpenAI Batch API; скидка Batch не применена. Фактическое списание неизвестно: поле стоимости провайдера остаётся `null`; приведённая сумма — оценка по токенам, не счёт OpenAI.

Для неуспешного полного v3 `run_batch.py` корректно сохранил агрегат usage как `null`: скрипт получает публичные оценки, а для неуспешного разговора оценки нет. Полные известные токены всех 72 попыток и кеш восстановлены read-only из локальных `documents` / `model_audit`, включая аудит неуспешного элемента. Неизвестные значения не заменялись нулём; при неполном аудите полный итог и стоимость остаются `null`, известная часть показывается отдельно. Во всех семи измерениях аудит полон.

Итоговый DEV v5 и репетиция используют версию чек-листа 3. Агрегаты и диагностические отчёты находятся в игнорируемой `data/quality/real/`, исходные ответы — в приватном `model_audit` базы `data/cqa.db`; в Git публикуются сводные числа и технические ID. Это только чтение SQLite; вызовов модели скрипт не делает.

Отсутствие 429 в конечном наборе запросов не гарантирует их отсутствие при другой нагрузке или лимитах аккаунта. C=4 проверен на полном DEV и контрольной репетиции без 429; эту настройку можно оставить для текущей нагрузки, сохранив обработку ограничений и повторов. Интервал `Retry-After` соблюдается полностью. Успешное прохождение проверки структуры не доказывает смысловую точность оценок: предварительная сверка описана в [QUALITY_NOTES.md](QUALITY_NOTES.md), а человеческих файлов `data/gold/*.json` пока нет; gold accuracy и MAE не измерены.

Это измерение повторяемости, не accuracy. Первый изменённый разговор исключён; детали и ограничения приведены в QUALITY_NOTES.
