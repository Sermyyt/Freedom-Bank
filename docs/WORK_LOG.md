## Разбор оставшихся мутаций

| Место | Почему изменение не различается в текущем валидированном процессе |
| --- | --- |
| evaluation.DomainError, default details | Все текущие вызывающие места не передают details; HTTP-конверт нормализует None и пустой список одинаково. Для будущего непустого details это не универсальная эквивалентность. |
| evaluation.cache_key / build_prompt, ensure_ascii (2 точки) | Меняется представление JSON, но не декодированные данные; кеш остаётся детерминированным. |
| evaluation._require_model_evidence, неполный диапазон | Та же недопустимая комбинация отклоняется следующим независимым валидатором диапазона. |
| evaluation, fallback client_facing | Импорт всегда сохраняет это обязательное поле; fallback не используется. |
| evaluation.validate_human_result, начальный manual_review | Значение затем явно устанавливается обработчиком решения человека. |
| evaluation._AttemptLog, начальный duration_ms | Успешный и ошибочный выходы заменяют его фактической длительностью. |
| evaluation._evaluate_selected, нижняя граница attempts (2 точки) | Settings допускает только положительное число попыток. |
| scoring, Decimal quantum 1 → 0 | quantize использует экспоненту quantum; коэффициенты 0 и 1 с той же экспонентой округляют одинаково. |

Машинные отчёты, LCOV и снимки мутаций остаются локально. Секреты, реальные транскрипты и сырой ответ настоящей модели в журнал не переносятся.
