# CQA — Freedom Broker

Подготовка к защите и 23-му часу: [RUNBOOK](docs/RUNBOOK.md), команды PowerShell, импорт и повтор ошибок, резервная копия и восстановление. Интерфейс после слияния frontend доступен на `http://127.0.0.1:8000/` через тот же сервер.

Из `backend/`: `python scripts/preflight.py --expected-dev-count 65 --expected-prompt-version cqa-v9`. Проверка только читает API и печатает OK/FAIL, код выхода 0 только при полной готовности. Оба флага необязательны: с ними требуется именно указанное число DEV и версия промпта; без них проверяется согласованность текущего сервера. Скрипт сверяет текущие ревизии DEV с активным чек-листом, `Health.prompt_version`, провайдером и моделью; demo, старые оценки и дубли не засчитываются. `dataset_ready` означает наличие настройки источника, не проверку доступности внешней ссылки. Страница `/` проверяется по HTTP/HTML, без проверки отрисовки JavaScript.

Шаблоны ручной разметки: `python scripts/make_gold_template.py p1-en-015 p1-ru-011 --group DEV --reviewer "Имя проверяющего"`. Скрипт создаёт `data/gold/<conversation_id>.json`, фиксирует текущую ревизию и активную версию чек-листа; существующие файлы пропускает. В каждом критерии есть `guidance` с описанием и допустимыми парами `status/value`. Человек копирует выбранную пару в пустое `answer`: например `{"status":"answered","value":false}` или разрешённый `{"status":"not_applicable","value":null}`. Подсказки оставлять можно: `eval_gold.py` их не использует для сравнения. Пустой ответ не считается меткой и отклоняется. Итог `total` не добавляется, чтобы пустое поле не стало разметкой нулевого итога; его можно добавить вручную. Для другой группы с такими же ID укажите отдельный `--output ../data/gold/CONTROL` и передайте эту папку в `eval_gold.py --gold`. Разметка и подсказки не содержат ответов модели или текстов разговоров и остаются вне Git.

Рабочий FastAPI-сервис с SQLite, динамическими чек-листами, пакетной оценкой и апелляциями.
По умолчанию `LLM_PROVIDER=fake`: оценки синтетические, для подключения фронтенда и проверки процесса.
Фронтенд должен постоянно показывать отметку «Демо: оценки синтетические» при `is_demo=true`.

FakeLLM показывает разные допустимые ответы: «Нет», ступени шкалы ниже максимальной, разрешённый N/A с причиной, ручную проверку и флаги нарушений. SHA-256 канонического JSON нормализованного `transcript` вместе с `criterion_id` делает выбор воспроизводимым: состав пакета, порядок критериев и повторные попытки его не меняют. Доказательство из неклиентской фазы `hold` / `internal_consult` вызывает штатное предупреждение о ручной проверке. Это демонстрация состояний интерфейса, а не смысловая оценка разговора.

Версия демо-поведения входит в ключ кеша. После её изменения создайте новую оценку: `force=true` для обхода старого кеша не нужен. Ранее сохранённые оценки остаются прежними. Локальная проверка на 65 DEV-разговорах дала идентичные повторные ответы, 48 разных итогов, 30 N/A по критериям, 16 разговоров с флагом грубого нарушения, 33 с ручной проверкой и 7 предупреждений по неклиентской фазе. Настоящая модель в этой проверке не вызывалась; эти числа не являются метриками качества.

## Подготовка в Windows PowerShell

В корне проекта, Python 3.11 или новее:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Set-Location backend
..\.venv\Scripts\python.exe -m pytest
```

Активация окружения не обязательна. После обновления проекта остановите API, повторите установку `requirements.txt` в его окружение и запустите сервер прежней командой: уже запущенный процесс не подхватит новые зависимости. После запуска обновите интерфейс сочетанием Ctrl+Shift+R.

HTTP-зависимости обновлены до FastAPI 0.162.2, Starlette 1.6.0 и python-multipart 0.0.33. Эти версии закрывают выявленные проблемы [Windows UNC в StaticFiles](https://github.com/Kludex/starlette/security/advisories/GHSA-wqp7-x3pw-xc5r), [обработки Range](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8) и [multipart-заголовков](https://github.com/Kludex/python-multipart/security/advisories/GHSA-pp6c-gr5w-3c5g). Starlette зафиксирован явно, чтобы установка не возвращала уязвимую транзитивную версию; сохранена совместимость с используемым httpx 0.28.1.

Для Python 3.14 требуется Pydantic 2.12 или новее: в `requirements.txt` разрешён диапазон `pydantic>=2.12,<3`. [Поддержка Python 3.14 появилась в Pydantic 2.12](https://pydantic.dev/articles/pydantic-v2-12-release). После обновления HTTP-зависимостей 2026-11-08 проверены отдельные окружения Windows на CPython 3.11.16, 3.12.14 и 3.14.7 с Pydantic 2.14.3 / pydantic-core 2.50.4: в каждом 493 теста прошли, конфликтов зависимостей нет. Два предупреждения об устаревающих интерфейсах Starlette/httpx и AnyIO остаются в тестовом стеке. Полная пересборка окружения по инструкции выше доступна и участнику с Python 3.14.

## Запуск API

Из `backend/`, без ключа модели:

```powershell
$env:LLM_PROVIDER = 'fake'
$env:CORS_ORIGINS = 'http://localhost:3000,http://127.0.0.1:5500'
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте [Swagger](http://127.0.0.1:8000/docs) или [health](http://127.0.0.1:8000/api/health).
База по умолчанию `data/cqa.db` в корне проекта. Перезапуск сохраняет разговоры, версии, оценки и историю.
Запускайте один серверный процесс (без `--workers`): очередь ограничена `LLM_MAX_CONCURRENCY`, незавершённые задания после аварийного перезапуска получают `INTERRUPTED_BY_RESTART`.
При наличии `frontend/` сервер раздаёт её с `/`; файлы интерфейса не изменяются.

Имена настроек и безопасные значения по умолчанию — в `.env.example`. Настройки читаются из окружения процесса; файл `.env` автоматически не читается.
Если вы вручную создали и заполнили `.env` в корне проекта, добавьте к команде запуска `--env-file ../.env`. Это явная загрузка конфигурации сервером; файл не входит в Git.
`DATASET_URL` нужен только для серверного импорта по группе. Для локального JSON используйте Swagger `POST /api/imports/file` (multipart `file`, группа для массива обязательна).
Не передавайте ключи и URL источника в браузер. Сервис предназначен для локальной демонстрации без авторизации.

```powershell
$health = Invoke-RestMethod http://127.0.0.1:8000/api/health
$job = Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/evaluations -ContentType 'application/json' -Body '{"group_id":"DEV"}'
Invoke-RestMethod ("http://127.0.0.1:8000/api/jobs/" + $job.data.id)
```

Группа должна быть предварительно импортирована. Альтернатива `group_id` — список `revision_ids`; одновременно их передавать нельзя.
Создание версии с `activate=true` требует `expected_latest_version_id` и явного `expected_active_version_id` из свежего health (в том числе `null`).
При конфликте API возвращает 409 без частичного сохранения. В ручной апелляции обязательна причина; отсутствующее обоснование берётся из неё, отсутствие доказательств даёт предупреждение.

## Проверки и репетиция

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe -m pytest
..\.venv\Scripts\python.exe scripts\gen_api_examples.py
..\.venv\Scripts\python.exe scripts\run_batch.py --group DEV
..\.venv\Scripts\python.exe scripts\rehearse_control.py
```

Первые две команды работают без сети и ключей; примеры получают ответы временного FastAPI-сервиса через TestClient и не используют DEV.
Последние две команды обращаются к локальному запущенному API. Репетиция читает локальный DEV, импортирует изменённый набор под новой группой и оценивает его текущим провайдером.
В demo это проверка совместимости, а не измерение точности ИИ. Реальная скорость и качество требуют отдельно настроенного провайдера и проверки человеком.

`run_batch.py` и `rehearse_control.py` ждут до 2400 с по умолчанию (`--timeout` меняет предел). ID созданного задания сразу печатается в stderr, до ожидания; JSON отчёта остаётся в stdout. Тайм-аут CLI не отменяет задание. `python scripts/run_batch.py --job-id <ID>` продолжает ожидание и собирает результат только через GET, без нового платного запуска. Его `duration_ms` — длительность текущей команды; для полного времени задания смотрите `started_at` / `finished_at` API. После тайм-аута репетиции используйте этот же способ, не импортируйте новую репетиционную группу.

Резервные копии: `python scripts/database_backup.py backup --database <DB> --output <NEW_BACKUP>` создаёт новый проверенный снимок через SQLite backup API, включая committed WAL. Для восстановления остановите все процессы этой БД и выполните `python scripts/database_backup.py restore --backup <BACKUP> --database <DB> --safety-backup <NEW_SAFETY_BACKUP> --server-stopped`. Восстановление существующей БД требует успешной защитной копии её текущего состояния; выбранная копия проверяется до замены, ни один существующий бэкап не перезаписывается. Полные команды Windows PowerShell 5.1 и пути вне Git — в RUNBOOK.

## Настоящая модель

Доступны `LLM_PROVIDER=openai` (Responses API) и `LLM_PROVIDER=anthropic` (Messages API).
Задайте в окружении `LLM_MODEL` и `LLM_API_KEY`; ключ вводится только локально и не попадает во фронтенд.
`LLM_BASE_URL` — необязательный адрес API, `LLM_MAX_OUTPUT_TOKENS` — лимит ответа (8192), `LLM_TIMEOUT` — тайм-аут одной попытки (60 секунд), `LLM_MAX_ATTEMPTS` — максимум попыток (3).
Выбранная модель должна поддерживать structured outputs с JSON Schema. Конкретная модель не зашита в коде.

При 429/5xx и сетевых ошибках предусмотрены ограниченные повторы с паузой; 400/401/403 не повторяются.
Если настройка отсутствует, health показывает `evaluation_ready=false`, запуск оценки возвращает 503. Сервер не подменяет настоящего провайдера демо-режимом.
Токены суммируются по всем попыткам, когда провайдер их сообщил. Неизвестная стоимость остаётся `null`.
Автоматические тесты используют MockTransport. Фактические замеры OpenAI gpt-4.1-mini и расходы по всем попыткам приведены в [DATA_NOTES](docs/DATA_NOTES.md); смысловые ошибки и неоднозначности — в [QUALITY_NOTES](docs/QUALITY_NOTES.md). Успешное завершение задания не означает правильность всех оценок. Человеческий gold хранится отдельно и не заменяется разбором ассистента.

В проверенной конфигурации на одинаковых исходных данных обнаружены изменения ответов между прогонами, включая флаг грубого нарушения. Автоматические оценки требуют проверки человеком; технический успех 65/65 не подтверждает смысловую воспроизводимость.

Последняя смысловая проверка восьми сложных разговоров выполнена на `cqa-v9`, версия чек-листа 5: шесть из семи прежних расхождений получили ожидаемые ответы, один случай отмечен для ручной проверки; появились четыре новые ошибки. Разбор 64 ответов: 45 согласий, 4 расхождения, 15 неоднозначностей. Это разбор ассистента, не accuracy; результаты и ограничения — в `docs/QUALITY_NOTES.md`. Затем весь DEV повторно оценён на v9: **65/65 за 636.954 с**, 1 ручная проверка, 0 упавших разговоров и 429, расчётные $0.812968. Живая замена критерия потребовала только 1 вызов и 4.964 с; исходная версия 5 восстановлена. Полные измерения — `docs/DATA_NOTES.md`. Контрольный изменённый набор целиком на v9 не повторялся; человеческая gold-разметка отсутствует.

С `cqa-v9` настоящие провайдеры оценивают каждый критерий отдельным вызовом с полным транскриптом. Это изолирует правила, увеличивая время и стоимость; `LLM_MAX_CONCURRENCY` по-прежнему ограничивает число одновременно обрабатываемых разговоров. Внутри разговора критерии выполняются последовательно, `LLM_MAX_ATTEMPTS` применяется к каждому такому вызову. Токены и `usage.calls` суммируют все вызовы и повторы; ошибочный критерий повторяется без повторного запроса уже принятых критериев. FakeLLM сохраняет пакетный режим. Публичная форма оценки не менялась.

Для повторения проверенной конфигурации из `backend/`, с заполненным локальным `.env`:

```powershell
$env:LLM_PROVIDER = 'openai'
$env:LLM_MODEL = 'gpt-4.1-mini'
$env:LLM_MAX_CONCURRENCY = '4'
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --env-file ../.env
```

Значения окружения процесса имеют приоритет над `.env`. Параллелизм 4 проверен на описанном в DATA_NOTES прогоне; лимиты другого аккаунта могут отличаться. Для нового измерения времени и качества используйте `scripts/run_batch.py --group DEV --force`, иначе сохранённые ответы могут быть переиспользованы. После изменения seed в существующей базе создайте и активируйте новую версию через API с проверкой обоих ожидаемых ID; перезапуск сам по себе не обновляет сохранённый чек-лист.

## Отчёт по данным

Сохраните полный ответ организаторов в `data/raw/DEV.json`. Для другого набора используйте другое имя файла. Файлы с реальными диалогами, отчёты с системными фразами и PDF не входят в Git.

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe scripts\data_report.py --file ..\data\raw\DEV.json --group DEV --output ..\data\reports\DEV.audit.json
```

`--group DEV` без `--file` выбирает локальный `data/raw/DEV.json`; сеть не используется. Если группа передана и в конверте, значения должны совпасть. Голый массив записей тоже поддерживается; при отсутствии группы в режиме аудита используется `UNSPECIFIED`.

При `--output` в консоль выводится только сводка; полный отчёт записывается в указанный путь. Без `--output` JSON-отчёт включает системные фразы и ID разговоров: не публикуйте его. URL внутри фраз удаляются из отчёта, исходный JSON не меняется. Код возврата 0 означает успешный анализ, 2 — ошибку файла/структуры/группы. Битые записи видны в skipped_records/errors и не мешают анализу остальных.

Дополнительный ручной загрузчик запускается из корня:

```powershell
.\.venv\Scripts\python.exe backend\scripts\fetch_dataset.py
```

Он запрашивает URL скрытым вводом и сохраняет успешный ответ в `data/raw/<dataset_group_id>.json` — каждый набор в свой файл, DEV не перезаписывается. Для контрольного набора вставьте ту же ссылку и укажите группу: `--group <ID>` меняет в ссылке только параметр `group_id`; ответ другой группы или небезопасный `dataset_group_id` отклоняется без сохранения. После этого `data_report.py --group <ID>` найдёт файл сам. Адрес не сохраняется в исходниках. Вариант `--encoded` предназначен для передачи base64 через автоматизированный скрытый ввод терминала, который иначе может терять специальные символы; base64 также является секретом, его нельзя сохранять в репозитории. Рабочий API уже использует `DATASET_URL` из серверной конфигурации для `POST /api/imports/dataset`; `.env` загружает сам сервер только при явном `--env-file`. Отдельный загрузчик получает ссылку скрытым вводом и не читает `.env`.

## Проверка качества по человеческой разметке

`scripts/eval_gold.py` сравнивает сохранённые оценки с локальными JSON-файлами из `data/gold/`. Разметку заполняет проверяющий после чтения разговоров и правил; скрипт её не создаёт и не вызывает модель. Метаданные `provenance` фиксируют заявленного автором проверяющего, но не удостоверяют его личность. Файлы разметки и отчёты остаются в игнорируемой `data/`.

Ниже только синтетический пример формата, а не разметка DEV и не измерение качества:

```json
{
  "schema_version": 1,
  "provenance": {"kind": "human", "reviewer": "local-reviewer-alias"},
  "cases": [{
    "group_id": "SYNTHETIC_EXAMPLE",
    "conversation_id": "example-001",
    "revision_id": "copy-ref.revision_id-from-api",
    "checklist_version_id": "copy-checklist-version-id-from-api",
    "criteria": [{
      "criterion_id": "copy-criterion-id-from-version",
      "answer": {"status": "answered", "value": false}
    }]
  }]
}
```

`conversation_id` здесь внешний ID источника. Каждому случаю нужен `revision_id` и/или `content_hash` текущей ревизии; хеш берётся из списка `/api/conversations/{id}/revisions`. Если заданы оба, проверяются оба. `criteria` содержит хотя бы одну метку; разрешена частичная разметка. Для шкалы передаётся допустимое число, для бинарного критерия или флага — boolean. `true` не равен `1`; числовые `1` и `1.0` равнозначны. N/A задаётся как `{"status":"not_applicable","value":null}` и разрешён только настройкой критерия. Необязательное `total` — ожидаемый итог от 0 до 100 либо явно `null`; отсутствие поля означает, что итог не размечен.

Из `backend/`, после импорта и оценки группы:

```powershell
..\.venv\Scripts\python.exe scripts\eval_gold.py --gold "..\data\gold\*.json" --output ..\data\reports\gold_eval.json
```

По умолчанию берётся самая новая **реальная** оценка текущей ревизии, затем проверяется её `checklist_version_id`. При изменившейся версии возвращается `VERSION_MISMATCH`; скрипт не откатывается к старой подходящей оценке. Сравнивается только `original`, поэтому ручное исправление через апелляцию не улучшает метрику модели. Для явной проверки механики демо допускается `--include-demo`; такой отчёт помечается `includes_demo`. Другой локальный сервер задаётся `--api-url`.

Отчёт показывает точное совпадение ответов по критериям, долю размеченных критериев `label_coverage`, пропущенные и ложные срабатывания флагов, а также MAE итогового балла. Доли находятся в диапазоне 0–1. Для флагов N/A считается отсутствием срабатывания, но сохраняется отдельным ответом при точном сравнении. Два направления ошибок N/A считаются отдельно: `false_positive_na` — модель ответила N/A при человеческом answered; `missed_na` — модель ответила answered при человеческом N/A. Эти счётчики есть как по каждому критерию, так и по всей выборке; пропуски и невалидные ответы в них не входят. Пропущенные/невалидные ответы модели, неизвестные критерии, устаревшие ревизии и отсутствующие оценки исключаются с кодом ошибки; они не превращаются в неверные ответы или нулевые баллы. MAE считается только по парам числовых итогов; совпадения и несовпадения с явным `null` учитываются отдельно. Случаи с одной парой `(group_id, conversation_id, checklist_version_id)`, повторённые внутри файла или между файлами, исключаются целиком, чтобы повторные метки не получали дополнительный вес.

В отчёт не попадают транскрипты, обоснования модели и имя проверяющего. `source_index` и `case_index` отсчитываются от нуля; файлы обрабатываются по отсортированным путям. `criteria_labeled`/`criteria_available` описывают случаи, прошедшие проверку ревизии, версии и меток; исключённые случаи видны в `errors` и `cases_excluded`. `total_compared` — число числовых пар для MAE. Код завершения `0` означает сформированный отчёт без исключений, а не высокое качество; `1` — частичный отчёт с исключениями, `2` — нет пригодных сравнений или ошибка запуска. Выходной файл не может совпадать с входной разметкой.
