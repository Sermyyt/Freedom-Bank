# CQA — Freedom Broker

Текущая стадия: раздел 1 BACKEND_SPEC.md, изучение материалов и проектирование API.
Рабочего HTTP-сервиса и оценщика пока нет. Следующая стадия начинается только после ответа человека на контрольной точке.

## Что подготовлено

- `AGENTS.md` — постоянные правила работы, исходная копия.
- `docs/BACKEND_SPEC.md` — исходное ТЗ, без редактирования.
- `docs/API_CONTRACT.md` — модели и маршруты для согласования с фронтендом.
- `docs/DECISIONS.md` — проверенные правила, уточнения и технические решения.
- `docs/DATA_NOTES.md` — результаты аудита и ограничения.
- `backend/scripts/data_report.py` — автономный анализ набора, без вызовов модели.
- `backend/app/data/system_events.json` — расширяемый словарь системных событий.
- `backend/tests/` — проверки аудита на синтетических данных и локальном DEV при его наличии.

## Подготовка в Windows PowerShell

В корне проекта, Python 3.11 или новее:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
Set-Location backend
..\.venv\Scripts\python.exe -m pytest
```

В текущей рабочей копии .venv уже подготовлена. Активация окружения не обязательна.

## Отчёт по данным

Сохраните полный ответ организаторов в `data/raw/DEV.json`. Для другого набора используйте другое имя файла. Файлы с реальными диалогами, отчёты с системными фразами и PDF не входят в Git.

Из `backend/`:

```powershell
..\.venv\Scripts\python.exe scripts\data_report.py --file ..\data\raw\DEV.json --group DEV --output ..\data\reports\DEV.audit.json
```

`--group DEV` без `--file` выбирает локальный `data/raw/DEV.json`; сеть не используется. Если группа передана и в конверте, значения должны совпасть. Голый массив записей тоже поддерживается; при отсутствии группы в режиме аудита используется `UNSPECIFIED`.

При `--output` в консоль выводится только сводка; полный отчёт записывается в указанный путь. Без `--output` JSON-отчёт включает системные фразы и ID разговоров: не публикуйте его. URL внутри фраз удаляются из отчёта, исходный JSON не меняется. Код возврата 0 означает успешный анализ, 2 — ошибку файла/структуры/группы. Битые записи видны в skipped_records/errors и не мешают анализу остальных.

Дополнительный ручной загрузчик запускается из корня:

```powershell
.\.venv\Scripts\python.exe backend\scripts\fetch_dataset.py
```

Он запрашивает URL скрытым вводом и сохраняет успешный DEV-ответ локально. Адрес не сохраняется в исходниках. Вариант `--encoded` предназначен для передачи base64 через автоматизированный скрытый ввод терминала, который иначе может терять специальные символы; base64 также является секретом, его нельзя сохранять в репозитории. Рабочий API в будущем получит DATASET_URL из серверной конфигурации; .env в этой стадии не создаётся и не читается.

## Источники

В локальной игнорируемой папке docs/source/ находятся гайд и чек-лист организаторов. Подробности и страницы, по которым приняты решения, указаны в docs/DECISIONS.md. Данные пользователя нельзя переносить в публичные тестовые примеры. docs/examples/ будет генерироваться из настоящих ответов FakeLLM API после его реализации, а не заполняться вручную сейчас.
